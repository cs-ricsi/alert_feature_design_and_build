# Project Brief

## Source

Product manager brief received at project kickoff.

## Original Product Brief

> We want users to be able to set up alerts so they get notified when something important happens in the world — like breaking news, market movements, natural disasters, that kind of thing. Should work for both email and Slack. Make it flexible enough that we can add more channels later. We need an admin view too.

## Delivery and Documentation Expectations

In addition to the product brief, the project deliverable is expected to include a documented record of the work process. This includes:

- a prompt history containing the prompts used during the project
- planning documents and implementation plans
- working artifacts created during the design and development process
- evidence of how the solution was approached and built

These process and documentation requirements are treated as part of the project deliverable alongside the MVP itself.

## Time Constraint

The work is being completed within a limited timeframe. This constraint materially affects scope, prioritization, and implementation depth, and therefore the project is approached as a timeboxed MVP rather than a full production-ready system.

## Context

This brief was provided as the sole initial product input for the implementation.

At the start of the project, no further specification was provided regarding:

- user flows
- UX or wireframes
- data model or schema
- event source integrations
- delivery infrastructure
- admin requirements in detail
- permission model
- non-functional requirements

## Purpose of this Document

This file preserves the original request, delivery expectations, and project constraints as the starting point for the implementation.

Interpretation of the brief, scoping decisions, implementation assumptions, architecture choices, and process documentation are captured separately in the rest of the `docs/` directory.
